# Remastered renderer integration plan

The first implementation stage is an offline asset reader and inspection path. It does not enable HD graphics in the Android app. Real Remastered samples are needed to verify the format assumptions and decide the first supported asset subset; synthetic tests alone cannot establish game compatibility.

## Current rendering path

| Location | Existing responsibility | Integration requirement |
| --- | --- | --- |
| `native/runtime.cpp`, `JNI(frame)` | Advances the game, calls `openbw_render`, copies the RGBA framebuffer into the Android bitmap. | Preserve simulation timing and the bitmap row-stride contract. |
| `native/generated/wasm_main.cpp`, `openbw_render` | Calls the native UI renderer. | Keep rendering changes separate from simulation state. |
| Generated `native-engine/ui/ui.h`, `draw_image`, `draw_sprite`, `draw_fog_snapshot`, `draw_sprites` | Draws classic indexed sprites in engine order, including remembered buildings. | Add an optional representation at the same image draw position, with classic fallback. |
| Generated `native-engine/ui/ui.h`, `update` | Draws terrain, sprites, fog, callbacks and native UI; then converts indexed pixels to RGBA. | Preserve this visibility and compositing order when adding color sprites. |
| `native/generated/wasm_backend.cpp` | Owns the software framebuffer, surface conversion and blitting. | Native RGBA byte order is red, green, blue, alpha; Java ARGB integers are a different representation. |
| `app/src/main/java/org/openbw/androidtest/NativeSurface.java`, `resizeWorld` and `drawBitmap(world, ...)` | Sizes the classic-resolution world bitmap and scales it onto the display. | Separate render pixel density from world viewport size and touch coordinates. |

Native engine sources are regenerated by `scripts/prepare_native.py`. Renderer changes must be reproducible through a new patch in that script's ordered patch stack, rather than edits only to generated `native-engine` files. Native changes also require rebuilt Android libraries; packaging existing binaries does not incorporate source changes.

The dormant `use_new_images` path is not a suitable shortcut. Its queued images draw after fog and native UI, its image loading backend returns null, and its sizing code assumes centered frames, uses a fixed scale and uses surface width for height. It lacks Remastered layer and team-color handling.

## Required integration contract

- **Identity and frames:** resolve an engine image type and its current classic frame to a validated Remastered entry. Do not infer identity solely from a shared GRP pointer or filename. Validate the frame count and mappings before enabling replacement. Keep animation advancement in the existing engine.
- **Frame anchors:** use the asset's frame rectangle, canvas dimensions and origin convention together with `get_image_map_position`, screen position and the engine's horizontal-flip state. An atlas rectangle is not a world-space origin. Establish the sign, units, HD/HD2 scale and mirrored anchor from a real sample; do not assume centered frames or square textures.
- **Depth and order:** preserve the engine's sprite ordering, each sprite's image ordering, and the placement of shadows, selection circles, health bars and other overlays. A replacement cannot simply be painted over the completed classic framebuffer: later classic images may need to occlude it. Fog, native UI and drag selection must retain their intended positions in the composition. Depth, normal and ambient-occlusion layers are data with separate shader semantics; decoding those layers does not implement their lighting or compositing behavior.
- **Fog:** use the same visibility decisions as the current renderer, including detached effects, cloaking/detection and saved building snapshots. A snapshot must use its captured image state, not query the live unit's current frame or ownership. Remastered rendering must never expose a hidden unit or its changes.
- **Color and effects:** decode textures into an explicitly documented RGBA representation, including straight versus premultiplied alpha. Apply the engine player's color through the actual Remastered team-color mask/layer rules. Preserve shadow and transparency behavior. Cloak, distortion, warp and glow image modifiers require dedicated support; use classic rendering for an unsupported combination.
- **Classic and EUD fallback:** missing assets, unknown formats, unsupported modifiers and invalid frame mappings must keep the image visible through the classic renderer. EUD edits can change GRP pixels, frame geometry, image references and palettes at runtime. Track relevant mutation/invalidation state and fall back for affected graphics, including changes made after an asset was cached. Merely finding an original matching asset is insufficient. See the existing `native-eud-grp103.patch` and `native-eud-image105.patch` paths.
- **Resolution and input:** an HD2 sprite needs a render target that retains its extra pixels. Increasing the existing resize dimensions also changes the viewport, so preserve world coordinates, camera bounds, minimap navigation and touch hit-testing while introducing an independent render scale. Existing zoom and aspect-ratio behavior must continue to work.
- **Resources and performance:** parse and validate outside the frame loop. Bound input size, atlas dimensions, decoded bytes and total resident texture memory; account for transient decode/upload copies. Cache by asset identity and graphics variant, and invalidate safely on data replacement. Avoid atlas decompression or disk reads per frame. Measure frame time, memory and upload cost on Android before expanding the supported set; a software preview is not evidence that a full HD battlefield will run acceptably.

Graphics packs need a separate import and cache lifecycle. The current document picker routes ZIP files through mission-package installation and MPQs through classic content preparation; it is not a CASC or Remastered importer. Menu art and portraits also have separate Java rendering paths and are outside an initial battlefield milestone.

## Smallest next milestone with real data

Use one user-owned extracted animation with its embedded layer payloads intact, original archive path, game build, graphics variant and corresponding classic image/frame identity. Prefer a unit with directional frames and visible player colors. Obtain the necessary classic MPQs for the existing renderer harness as well. Do not commit these assets to the repository.

First verify decoded colors, layers, frame rectangles, anchors and flips in an inspection preview against that sample. Then implement one opt-in unit replacement in a deterministic native scene, at the correct draw position and render scale, with classic fallback. Terrain, UI, portraits and a general CASC importer can follow independently. A successful texture decode is not the completion criterion for the renderer milestone.

Acceptance checks should cover team colors, overlapping classic/HD images, fog entry and exit, remembered buildings, unsupported modifiers, EUD changes after caching, camera zoom and map edges. Reuse `tests/run_fog115.py` and the native rendering harness pattern, capture the actual RGBA output, and verify that simulation hashes remain unchanged. Keep the standalone malformed-file and resource-limit tests runnable without licensed assets. Record real-sample validation separately from synthetic coverage.
